# 第二階段：正式雲端測試

## 需要你先準備

1. 在 Supabase 建立一個新 Project，區域選擇亞洲／新加坡附近的區域。
2. 在 SQL Editor 執行 `supabase/schema.sql`。
3. 到 Project Settings > API，取得：
   - Project URL
   - anon public key
4. 把兩項資料填入本機 `.env.local`：

```env
VITE_SUPABASE_URL=https://你的專案.supabase.co
VITE_SUPABASE_ANON_KEY=你的anon-public-key
```

不要把 `service_role` key 放入 `VITE_` 變數，也不要提交到 Git。

## 正式網址設定

在 DNS 管理 `jiggerflip.com` 的地方新增：

```text
Type: CNAME
Name: staff
Value: 由部署平台提供的目標
```

部署平台設定：

- Build command: `npm run build`
- Output directory: `dist`
- Environment variables: `.env.local` 中的 `VITE_` 變數
- Custom domain: `staff.jiggerflip.com`

## 測試帳戶

先建立三個測試帳戶，不要使用真實身份證或銀行資料：

- `admin-test`：管理員
- `manager-test`：主管
- `employee-test`：一般員工

測試資料只使用假姓名、假電話及假銀行資料。正式敏感資料要由伺服器端加密服務寫入，不能由前端直接保存。

## 第二階段驗收清單

- OTP 登入後重新開啟瀏覽器仍保持登入狀態
- 一般員工不能查看其他人的身份證及銀行資料
- 主管可查看及審批補卡，但不能查看銀行資料
- 管理員查看敏感資料時產生審計紀錄
- 4C 工作室 50 米內打卡為已驗證
- 超出 50 米仍可打卡，狀態為需要主管核實
- 跨日班次 `16:00–01:30` 正確計算
- 遲到通知送達主管
- 補卡申請及審批紀錄完整保存
- 匯出報表不包含銀行戶口資料
- 手機 Safari 及 Chrome 均可完成打卡

## 安全要求

- 正式網址必須使用 HTTPS。
- `service_role` key 只可放在伺服器端或 Edge Function。
- RLS policy 完成前，不要匯入真實員工資料。
- 敏感資料使用伺服器端加密，前端只收到遮罩值。
